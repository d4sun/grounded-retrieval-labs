Rich Answers, Not Just Text

Multimodal Retrieval over Technical Manuals

A build brief for engineers. You get the requirements, the reference diagrams, and a backlog of epics, user stories and tasks. You plan the system and implement it with your coding agent. The stack is free end to end.

Participant Brief & Build Backlog
Companion to the facilitator playbook · Sub-Track 1A: The Grounded Agent

1 · The brief

Field engineers don't want a paragraph about a wiring diagram — they want the diagram, and the page it's on. Build a retrieval system over technical manuals (PDFs, including scans) that, when a figure or table is the answer, returns the actual artefact with its page/source citation — not a prose paraphrase.

Guiding principle — retrieve-by-text, answer-with-artefact. Index something searchable (a caption, a linearised table, OCR text), but hand back the original figure/table, linked by provenance.

The three non-negotiables

01

Route content types

Text, figures, tables and scanned pages each take a different path. Don't let a diagram collapse into flat text.

02

Make figures & tables retrievable

An image doesn't retrieve on its own. A description of it does — caption figures, linearise tables.

03

Carry provenance end-to-end

doc → page → id on every unit, so an answer can show and cite the real thing.

What success looks like. Ask “show the relay control wiring” and get back the actual figure image with amt_handbook p.212 — not a sentence describing it. Ask for a torque spec and get the exact table rows + page.

3 · How you'll work

This is an agent-driven build. You own the architecture and the decisions; your coding agent writes most of the code. There are no hard-and-fast rules on implementation — pick your libraries from the free menu in §6 and justify your choices. What we care about is the three non-negotiables and that you can measure what you built.

Rhythm

  • Work in thin vertical slices — one epic at a time, ingest→answer before polishing any stage.
  • Use a feature branch per epic; keep commits small and reviewable.
  • Write a test as you finish each stage; a synthetic 2-page PDF is enough to start.
  • Record a baseline the moment retrieval works end-to-end, before any tuning.

What to hand your agent

  • This brief + the backlog below as the plan.
  • The three non-negotiables as acceptance gates it must not skip.
  • The failure-mode table (§Appendix) as its debugging checklist.
  • Review its plan before it codes; make it show provenance and per-type eval.

4 · Build backlog

Epics map to the pipeline stages. Stories and tasks are a starting point, not a contract — reshape them. The Done when criteria are the part to respect: they encode the non-negotiables.

E0Environment & corpussetup

Stand up a free, reproducible workspace and get a small multimodal corpus that ships evaluation gold.

Story E0.1 — As an engineer, I want a one-command, free setup so anyone can reproduce the lab with no billing wall.
What needs to be done
  • Create a virtualenv; keep a light core (parsing + index) so the offline path installs fast — no torch/CUDA required to start.
  • Make every model swappable free↔local from one config file; keep no paid key on the default path.
  • Expose a single `smoke` command that runs ingest→answer→evaluate end-to-end with no network.
Acceptance
  • A fresh clone installs and runs the smoke path with no API key and no GPU.
Story E0.2 — As an engineer, I want a small corpus with page-level evidence labels so I can measure retrieval objectively.
What needs to be done
  • Pull an eval slice that ships gold evidence (DUDE or MP-DocVQA).
  • Add one real manual (an FAA handbook, or a few iFixit guides) for the live ‘return the real figure’ demo.
  • Cap the corpus to a few hundred pages so iteration stays fast.
Acceptance
  • Corpus loaded; every gold question names a doc + its evidence page(s).
E1Parse & route content types[1]

Turn each PDF into routed text / figure / table regions with page numbers, and handle scanned pages safely.

Story E1.1 — As an engineer, I want each content type routed correctly so figures and tables aren’t lost as flat text.
What needs to be done
  • Run a structural parser (Docling, or a PyMuPDF route) to get text blocks, figure regions and table regions.
  • Attach a page number to every region; preserve reading order.
  • Decide the first loader you’d reach for — and note exactly what it would drop (the diagram? the table structure?).
Acceptance
  • Every page is classified; each figure/table region carries a page number.
Story E1.2 — As an engineer, I want scanned pages OCR’d behind a quality gate so garbled text never silently enters the index.
What needs to be done
  • Detect image-only pages (no text layer + a page-filling image).
  • Render and OCR them (Tesseract or equiv).
  • Score the output (mean confidence + garbled-char ratio); send failures to a review queue instead of the index.
Acceptance
  • Scanned pages are OCR’d or flagged; a review queue exists; sub-threshold pages are never indexed.
E2Extract figures & tables with provenance[2]

Make figures and tables first-class units, each able to name the exact page it came from.

Story E2.1 — As an engineer, I want the real figure image exported so I can hand it back as the answer.
What needs to be done
  • For each figure region, export the cropped image — the embedded raster where possible, else render the bbox.
  • Record doc→page→figure_id, the bbox, and any nearby caption text on the unit.
  • Filter out rules/icons below a minimum size so they aren’t mistaken for figures.
Acceptance
  • Figure images are written to disk; each one resolves to its exact page.
Story E2.2 — As an engineer, I want tables kept as structured rows/cols so I never flatten them.
What needs to be done
  • Extract each table preserving rows/cols (Camelot / pdfplumber / parser tables).
  • Store the structured form plus the source-page reference; keep the caption.
  • Leave `search_text` empty here — enrichment fills it; the structure is the artefact you return.
Acceptance
  • Tables stored structured + page; no table is reduced to a flat string.
Story E2.3 — As an engineer, I want a provenance spot-check so I catch lost citations before building on them.
What needs to be done
  • Sample five units by hand and confirm each can name the exact page it came from.
  • Fix provenance now if any can’t — everything downstream depends on it.
Acceptance
  • Spot-check passes: every sampled unit resolves to a page.
E3Enrich: caption & linearise[3]

Make figures and tables retrievable by giving them searchable text — without discarding the artefact.

Story E3.1 — As an engineer, I want each figure described for search so an image can be found by a text query.
What needs to be done
  • Send each figure image to a free vision model with a search prompt (component/system, visible labels, part numbers).
  • Store the caption as the figure’s `search_text`, linked to the original image + page.
  • Cache captions on disk and caption selectively (figure/table pages only); keep a local model as fallback for rate limits or sensitive data.
Acceptance
  • Every figure unit has non-empty search_text; re-runs are served from cache; the image is untouched.
Story E3.2 — As an engineer, I want tables linearised to text while keeping the structured copy for the answer.
What needs to be done
  • Turn each table into searchable text (markdown or col=value rows); normalise the spacing/newline noise PDF extractors introduce.
  • Include the table’s caption and nearby headings in the search text.
  • Keep the structured cells as the artefact — linearisation is for search only.
Acceptance
  • Every table unit has search_text; the structured cells are unchanged.
E4Embed & index[4]

Build one index over text + figure-caption + table-text, with provenance in metadata.

Story E4.1 — As an engineer, I want a single mixed index so one query can reach any content type.
What needs to be done
  • Embed `search_text` with a free local model (e.g. bge-small-en-v1.5).
  • Chunk prose by structure/heading; keep a table or a figure-caption as ONE unit (don’t split).
  • Index all unit types together (FAISS or equiv).
Acceptance
  • Index persists; text, figure-caption and table-text units are all present and searchable.
Story E4.2 — As an engineer, I want provenance stored next to every vector so hits can be cited.
What needs to be done
  • Write each unit’s full provenance (doc→page→id, bbox, source path) into the index metadata.
  • Persist units + vectors together so a reload reconstructs citations.
Acceptance
  • Each indexed row carries doc→page→id; reloading the index preserves citations.
E5Retrieve[5]

Return the top-k units with their provenance; make exact identifiers findable.

Story E5.1 — As an engineer, I want retrieval to return citations so every hit is traceable.
What needs to be done
  • Implement retrieve(query, k) returning the top-k units with their provenance and scores.
  • Surface a human-readable citation (e.g. `doc p.212`) on every hit.
Acceptance
  • Retrieval returns units, each with a resolvable citation.
Story E5.2 — As an engineer, I want exact codes (part/fault numbers) to match so dense vectors don’t smear them.
What needs to be done
  • Add a lexical BM25 scorer over the same search texts.
  • Fuse BM25 with the vector score (min-max normalise both; weight with an alpha you can tune).
  • Test on a fault-code / part-number query and compare fused vs vector-only ranking.
Acceptance
  • An exact-identifier query surfaces the right unit at or near the top.
E6Answer with the artefact[6]

Decide text / figure / table and return the REAL artefact + citation — never a paraphrase, never un-sourced.

Story E6.1 — As a field engineer, I want the actual figure/table when that’s the answer, not a description of it.
What needs to be done
  • Decide the answer type from the top SOURCED hit.
  • Figure → return the image path + page (optionally a one-line grounded caption). Table → return the exact rows + page. Text → the span + page.
  • Keep the structured/real artefact in the response, not a paraphrase of it.
Acceptance
  • Figure and table answers return the real artefact plus its page citation.
Story E6.2 — As an engineer, I want the system to abstain when nothing has provenance so I never cite nothing.
What needs to be done
  • Filter out any retrieved unit whose provenance can’t name a page before choosing an answer.
  • If no sourced unit remains, abstain and say why rather than presenting an un-sourced hit.
Acceptance
  • No-provenance hits are never presented as sourced; the system abstains cleanly when it must.
E7Evaluate & engineer against failures[7]

Measure retrieval BY TYPE, record a baseline, then fix measured failure modes.

Story E7.1 — As an engineer, I want recall@k / MRR split by type so a good aggregate can’t hide that figures retrieve badly.
What needs to be done
  • Using the gold evidence pages, mark a hit relevant when its provenance matches the gold doc + page.
  • Compute recall@k and MRR broken out by text / figure / table.
  • Record the baseline numbers BEFORE any tuning.
Acceptance
  • Per-type metrics are reported and a baseline is recorded.
Story E7.2 — As an engineer, I want a faithfulness check so an answer that shows the WRONG figure is caught.
What needs to be done
  • Spot-check five answers: does each show/cite the exact source artefact on a gold evidence page?
  • Flag the dangerous case — reads well but shows the wrong figure.
Acceptance
  • Five answers reviewed; any wrong-artefact answer is flagged.
Story E7.3 — As an engineer, I want to fix measured failure modes so the system improves with evidence.
What needs to be done
  • Pick two failure modes from the Appendix table.
  • Reproduce each from its measured symptom, apply the fix, and re-measure.
  • Show before/after numbers for each.
Acceptance
  • Two failure modes fixed, each with before/after metrics.

5 · Guidelines

Engineering

  • Provenance is sacred. If a unit can't name its page, it can't be a sourced answer. Carry doc→page→id from extraction to the final citation.
  • Fail closed. Prefer abstaining over citing nothing. A confident answer on the wrong figure is the most dangerous outcome — design so it can't happen silently.
  • Keep structure. Return structured table rows, not a flattened string. Keep the search copy (linearised) separate from the artefact.
  • Measure by type. A good aggregate recall can hide that figures retrieve terribly. Always break metrics out by text / figure / table.
  • Cache the expensive calls. Vision captioning is the one metered step — cache it, caption selectively, keep a local fallback.
  • Record a baseline before tuning so every change has a before/after.

Working with your agent

  • Give it the plan, then let it propose an approach; correct the plan, not every line.
  • Make it write the provenance spot-check and the per-type eval — don't accept a stage without them.
  • Have it keep the code modular (one package per stage) so you can swap a backend without a rewrite.
  • When it gets stuck, point it at the failure-mode table rather than prescribing the fix.
Cost & privacy. Use free endpoints with the public datasets only. Never send confidential manuals to a free endpoint — for real data, switch captioning and embeddings to local models so no bytes leave the machine. This is itself a production lesson (data residency / tenancy).

8 · Definition of Done

You're done when every box is ticked — these are the milestone gates, not the implementation.

  • Corpus loaded (eval set with evidence labels + one real manual).
  • Content routed; scanned pages OCR'd behind a quality gate.
  • Figures & tables extracted with doc→page→id provenance.
  • Figures captioned / tables linearised (free vision model, cached).
  • Mixed index built with provenance in metadata (local embeddings + FAISS).
  • Retrieval returns units with citations.
  • Answer step returns the real figure/table + page, not a paraphrase.
  • Retrieval measured by type; baseline recorded; 2 failure modes fixed with before/after.

Stretch goals

  • BM25 + vector fusion for exact identifiers (sets up Lab B).
  • ColPali / ColQwen2 page-image retrieval as a second index.
  • Local vision fallback when the free tier rate-limits you.
  • Multi-hop retrieval (Lab B) and trust/abstention (Lab C) on top of this corpus.
